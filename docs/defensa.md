# Defensa

## Ruta normal y de error
Cada tarjeta tiene una **ruta principal** (Inicio → Acción → Confirmación) y una **ruta de error** (guard de validación o estado de error → recuperación).

## Requisito explicado en código
El prototipo en Penpot se generó con la API del plugin; cada pantalla corresponde a un requisito (ver matriz de trazabilidad de cada tarjeta).

## Mejora vinculada al Issue
Cada tarjeta sigue el ciclo: fallo detectado → corrección aplicada → Issue en GitHub (con hallazgo, severidad, responsable, reproducción, decisión de cierre y enlace a commit/PR).

## Revisión cruzada (PR revisado)
Cada integrante revisa de forma fundamentada el PR de un compañero.

## Modificación en vivo (validación / feedback / foco)
Cada integrante debe poder modificar en vivo una validación, un feedback o el foco de su prototipo.
